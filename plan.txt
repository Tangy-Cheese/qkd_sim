Noisy QKD Network Simulator
------------------------------------------------------------

1. Project Overview

This project aims to design and implement a modular, research-oriented simulator for noisy Quantum Key Distribution (QKD) networks. 
The simulator will model realistic physical imperfections in fibre-based quantum channels and detectors and evaluate secret key rates
for multiple QKD protocols embedded within arbitrary network topologies.

The core objective is to build a clean, extensible architecture that separates:

- Physical modelling (loss, noise, detection)
- Protocol logic (BB84, E91, MDI-QKD)
- Network-level behaviour (routing and key management)

The simulator will support three QKD protocol families:

- BB84 (prepare-and-measure baseline)
- E91 (entanglement-based QKD)
- MDI-QKD (measurement-device-independent QKD)

The final system should allow reproducible simulations of secret key throughput as a function of distance, detector quality, noise 
parameters, and network topology.

------------------------------------------------------------

2. Physical Modelling Layer

The simulator will model realistic imperfections present in fibre-based QKD systems:

- Fibre attenuation (e.g. 0.2 dB/km)
- Detector efficiency
- Dark count probability per detection gate
- Basis misalignment / depolarising noise
- Channel visibility
- Background noise (optional extension)

From these parameters, the simulator will compute:

- Channel transmittance as a function of distance
- Detection probabilities
- Gains and yields
- Quantum Bit Error Rate (QBER)
- Secret key rate inputs for each protocol

This layer must be independent of the protocol so that all protocols share identical physical assumptions.

------------------------------------------------------------

3. Protocol Layer

Each protocol will be implemented as a modular component built on top of the shared physical models.

3.1 BB84 (Prepare-and-Measure)

Objectives:

- Simulate state preparation and basis choice
- Compute sifted key rate under loss and detector noise
- Derive QBER from misalignment and dark counts
- Implement asymptotic secret key rate formula
- Analyse key rate vs distance

BB84 will serve as the foundational validation protocol and baseline comparison.

3.2 E91 (Entanglement-Based QKD)

Objectives:

- Model entangled photon pair source
- Simulate two noisy channels to separate parties
- Compute correlation visibility
- Derive QBER from imperfect correlations
- Implement entanglement-based secret key rate formula

E91 allows comparison between prepare-and-measure and entanglement-based security approaches under identical noise conditions.

3.3 MDI-QKD (Measurement-Device-Independent QKD)

Objectives:

- Model two independent transmitters sending states to a central relay
- Simulate Bell-state measurement (BSM) at the relay
- Compute detection yields and error rates
- Derive secret key rate under symmetric and asymmetric distances
- Analyse detector efficiency and dark count thresholds

MDI-QKD is the most technically demanding protocol and demonstrates modern security-motivated QKD design.

------------------------------------------------------------

4. Network Layer

Beyond single-link simulations, the project will embed QKD links into network topologies.

Objectives:

- Represent nodes and quantum links as a graph
- Allow arbitrary topologies (line, star, mesh)
- Assign protocol type per link
- Compute link-level secret key rates
- Implement routing strategies to maximise end-to-end key throughput
- Model key pools and key consumption

The network layer should evaluate:

- End-to-end key rate between distant nodes
- Throughput sensitivity to topology
- Performance differences between protocol families in identical networks

------------------------------------------------------------

5. Simulation Framework

The simulator will support reproducible parameter sweeps and controlled experiments.

Potential experiments:

- Key rate vs distance (BB84, E91, MDI comparison)
- Sensitivity to detector efficiency
- Sensitivity to dark counts
- Effect of misalignment on QBER
- Network throughput vs topology
- MDI threshold behaviour under increasing loss

All experiments should produce structured output (e.g., CSV/JSON) and high-quality plots suitable for reporting.

------------------------------------------------------------

6. Software Architecture Goals

The project must emphasise clean object-oriented design:

- Clear separation between physical models and protocol logic
- Protocols implemented as interchangeable modules
- Network layer independent of protocol internals
- Configuration-based simulation runs
- Reproducible experiments with fixed random seeds
- Unit tests for each protocol component

The final codebase should resemble a research tool rather than a collection of scripts.

------------------------------------------------------------

7. Development Roadmap

Phase 1:
- Implement channel and detector models
- Implement single-link BB84 simulation
- Validate expected key rate decay with distance

Phase 2:
- Implement E91 protocol
- Compare BB84 vs E91 under identical physical parameters

Phase 3:
- Implement MDI-QKD single-link simulation
- Validate symmetric relay behaviour and detector efficiency thresholds

Phase 4:
- Implement network abstraction and routing
- Perform multi-node experiments
- Benchmark protocol performance across network scenarios

------------------------------------------------------------

8. Expected Outcomes

By completion, the project should provide:

- A modular QKD simulation framework
- Comparative analysis of BB84, E91, and MDI-QKD
- Network-level secret key throughput evaluation
- Sensitivity analysis under realistic noise models
- A reproducible, documented codebase suitable for research demonstration
